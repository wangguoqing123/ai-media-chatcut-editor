# 口播精剪：气口、停顿、口误和重复

先读取主片、可用脚本与完整转写，理解句子跨段关系，再决定保留与删除。用户已指定只包装、不动口播时，保留已确认的结构。

## 处理顺序

1. 转写未就绪时，按当前Hosted工具状态触发或等待同一任务；不要重复提交。ASR把产品名、人名听错时，先核对原声，再修转写；改识别文字不等于剪掉声音。
2. `read_script`读取当前Script，先理解全文。固定无意义犹豫音和长停顿可以做机械预清理；`clean_script`会直接改时间线，没有预览。用户要求先看删改方案时，先整理方案，不运行它。
3. 机械清理后重新读取最新Script，再做语义删改。用`read_script → 按实际返回路径编辑timeline.md → apply_script`处理口误重录、重复表达等语义问题；按当前工具规则使用可撤销删除标记，不靠删除转写词来纠正ASR。
4. 应用后回读新Script，检查句子是否完整、连接是否自然，是否仍有重复或多删。口播稳定后再做字幕、B-roll、MG动画和声音包装。
5. 语音结构改过后，检查所有已有依赖层的同步。需要时运行当前`smooth_audio`平滑音频剪点，随后抽听，不能用淡化掩盖被切掉的尾字。

Hosted与Desktop的导入、项目绑定和工具前缀不同。这里借鉴语义清理方法，执行时保持Hosted路线，不复制本机Desktop Skill里的`push_asset`或固定当前项目假设。

## 怎么判断

| 情况 | 动作 |
|---|---|
| 明显吸气突响、开口前的无意义等待 | 缩短或移除对应范围，保留随后完整发音；不把正常短呼吸全部抹掉 |
| 句中长停顿、想词停顿 | 压缩到自然衔接，不全部归零；转折、强调和章节停顿适当保留 |
| 无意义“呃、额”等犹豫音 | 可以清理；与前后发音粘连时选更保守的边界 |
| “所以、但是、然后、就是”等词 | 按上下文判断，承担因果、转折、步骤或语气时保留 |
| 同一句重录多遍 | 保留最完整清楚的一次，不机械保留最后一次；前一次独有的有效铺垫应保留 |
| 重复表达一个意思 | 只有完整版本覆盖了之前的信息才删；补充条件、例外或情绪的内容不是废话 |
| 说错后改口、半句放弃 | 删失败部分，保留自然连接的完整表达；不跨重录硬拼半句话 |
| 用户给定稿 | 按其指定词句边界匹配，不擅自改观点、补句或用新配音代替 |

不默认1.1倍速，不为了短而删掉“可能、不是、仅限”等限定词，不给原片未说出的句子造音。用户授权改写／补配音时另按其明确范围处理。

## 停顿参数

先听原声，结合用户节奏要求和当前官方工具的阈值选择起点。不要把“所有大于某固定时长都删光”作为通用规则。句间要有可感知的断句，重点或转场可更长；无意义长等候应明显收紧。

记录本次实际采用的停顿处理方式。参数只能帮助批量处理，不能替代语义判断和剪点试听。不能在唯一主画面轨道制造空的Script gap当呼吸，否则可能出现黑帧；需要停顿时保留源片静音区，或用真实覆盖画面承接。

## 最少回看范围

开头和结尾、每个删句／重录衔接点、最长停顿、最快和最轻语段都要检查。保留字头字尾、呼吸自然、嘴型与声音同步，画面无意外黑帧、跳回旧句或残留口误。

能播放就实际试听。只能读转写、波形或工具状态时，清楚标记“听感未验证”，不能宣称气口和声音完全自然。对用户说明实际删了什么内容，不用内部片段ID、词索引解释。
